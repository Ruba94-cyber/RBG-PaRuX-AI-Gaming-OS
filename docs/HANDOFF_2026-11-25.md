5. Read `PARUX_EXECUTION_PLAN.md` (first paragraphs) and this file, then continue with section 3.

## 6. Signing and release material

Never in the repository. The release manifest key, the Android keystore and the Authenticode certificate, with their password files, are kept by the owner outside the project. Transfer them to a new PC through a secure channel of the owner's choice. The scripts read them from environment variables set only inside the build process: `PARUX_SIGN_PFX`, `PARUX_SIGN_PFX_PASSWORD`, `PARUX_RELEASE_PRIVATE_KEY`, `PARUX_RELEASE_KEY_PASSWORD`, `PARUX_ANDROID_KEYSTORE`, `PARUX_ANDROID_STORE_PASSWORD`, `PARUX_ANDROID_KEY_PASSWORD`. The Android keystore password equals the manifest key password. Never print these values or write them to logs.

Corporate Lite assets are pinned (llama.cpp b12283, Vulkan b10549, Qwen3-4B, Qwen3-0.6B, multilingual-e5-small, mmarco reranker) and verified by SHA-256 in `scripts/build-corporate-lite.ps1`; use `-RuntimeTag b12283` and do not fetch unreviewed tags. MSI redistributables (ViGEmBus 1.22.0, HidHide 1.5.230, Sunshine ZIP) are pinned in `packaging/redist-installers.lock.json`.

## 7. Cautions learned this session

- Worktrees created for sub-agents can start from an old base: merge `main` first.
- A GitHub release needs the full 40-character commit SHA as `--target`.
- Windows on the owner's PC elevates administrators without a prompt, so an elevated `msiexec` runs unattended; on other PCs a UAC prompt cannot be driven by automation.
- Keep PaRuX closed (`PaRuX.exe --exit`) before applying settings migrations, and always keep a backup.
- The Ollama cancellation test is timing sensitive under load (now 30 s waits). If any test fails only in the full run, rerun it alone before treating it as a defect.
- The folder that hosted this work (`Desktop\PaRuX - archivio locale`) is meant to be deletable once development ends; nothing the installed app needs lives in it.
